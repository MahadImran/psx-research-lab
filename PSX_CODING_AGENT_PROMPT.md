# Message to give your coding agent

You are the lead engineer for **PSX Research Lab**, a private-first, zero-dollar Pakistan Stock Exchange market research platform with historical data, scheduled quotes, deterministic strategy backtesting, and conversational AI that translates natural language into experiment definitions. Read `PSX_RESEARCH_LAB_MASTER_SPEC.md` fully before writing code. Treat it as the technical contract.

## Operating rules
1. **Do not build everything in one pass.** Work through M0–M6, stopping after EACH milestone to run tests, write a concise report, and commit to GitHub. Start with M0 and M1 only. Never claim a data source or integration works without obtaining and recording a real successful response on a GitHub-hosted runner. For endpoints you cannot access, use clearly labeled fixtures and record blockers.
2. **Exactly $0 recurring hosting/API spend.** No paid plans, no R2, no paid workers, no paid AI fallback, no billable CI, no credit-card-dependent upgrade. Run Python only in hosted GitHub Actions Linux runners; use Cloudflare Workers Free + D1 + KV + static assets for serving and scheduling watchdog; use free Gemini API only. Absolutely no Orange Pi, Mac, personal hardware, paid server, or always-on machine is required. Any feature requiring a paid service must fail disabled and offer a free alternative.
3. **No public release.** Keep development local until Cloudflare Access Free is configured and tested to restrict the entire staging hostname; no unprotected publication of third-party market archives, datasets, or private experimentation data.
4. **Protect data and avoid abuse.** One collector owns all PSX access. Use `psx-dps` as primary adapter, `psxdata` as alternate, and PSXpert as unverified historical seed. Audit direct source formats, store raw responses, hash, validate, quarantine suspicious data, publish only last trusted versions. Respect 429/503 cooldown and Retry-After, never rotate proxies or bypass source blocks, never loop per stock on a timer. Never flood a source during backfill; start with a 250-upstream-request/day app fuse.
5. **Data durability.** Durable compressed raw PSX data and versioned encrypted exports live in a separate private GitHub data repository; Cloudflare D1/KV hold the canonical serving records. GitHub-hosted runners are ephemeral, so never rely on runner disk or Actions artifacts for persistence. Implement checksum manifests, idempotent publishing, retries from durable archives, GitHub backup commits, D1 exports, independently verified restore tests, and shared persistent D1 leases/source request budgets. Do not delete unique observations. Document realistic RPO/RTO limitations.
6. **AI is a compiler, not a financial calculator.** Use Gemini `gemini-3.5-flash-lite` with structured JSON that maps to a versioned, whitelisted strategy DSL; validate server-side; compute backtests deterministically in browser Web Worker. No executing generated code or arbitrary SQL, no trusting AI return numbers, no tools enabling web/code execution. Show assumptions and data quality, branching history and comparison charts.
7. **IssueTwin-style community AI quota.** Implement default global 50/day, visitor 5/day, minimum 30 seconds between calls, strict token caps, one active call/visitor, atomic D1 reservation and idempotency, provider 429 cooldown. Display *application quota* (never pretend to know actual Google remaining quota), model and reset time. Ask owner to verify available free Gemini RPM/TPM/RPD before enabling AI and lower defaults if needed. No calls if quota/DB/auth unavailable. Continue manual experiments when AI is disabled.
8. **Security.** Secrets through local `.dev.vars` (gitignored) and Cloudflare Worker Secrets; no real credentials in code, commit, logs, conversation, or screenshots. Cloudflare Access private staging; authz on admin routes; HMAC signed timestamped GitHub Actions ingestion requests passing Cloudflare Access service-token authentication, replay protection, scoped GitHub Actions and Cloudflare secrets, parameterized SQL, CSP and XSS protection, input and upload limits. Do not use or expose any owner-hosted devices. Fail closed if a security control is unavailable.
9. **Engineering quality.** TypeScript strict mode, Zod validation, Python typed code, pytest, Vitest, Playwright, fixtures of PSX data, integration tests and failure-injection tests. Pin exact dependency versions/commits, lint, format, test and provide docs. No unreviewed `curl | bash`, no raw shell eval of AI-generated content. Maintain data lineage and timestamps with `Asia/Karachi` for market times and UTC for system logs.
10. **Experience.** Build a fast, distinctive non-cookie-cutter financial terminal UI with excellent charts, search, compare, provenance and stale-data status, not a generic gradient/tile AI dashboard. Excellent accessible, responsive light/dark mode. Make every error actionable and non-destructive.
